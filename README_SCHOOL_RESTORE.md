# 서당 배치 복구 및 원인 확인 — 추가 배치 변경 없음

## 복구 범위
방금 적용했던 '칠판을 아래로 내리기'와 '뒤쪽 책장을 벽 쪽으로 밀기'를 취소했습니다.
복구 기준은 직전 gensokyo_rpg_school_layout_dev입니다.
칠판·교탁 정렬과 작은 책장 제거를 했던 첫 배치 정리 상태를 유지합니다.

school/terakoya.before-layout-v2.js를 school/terakoya.js로 그대로 복사했습니다.
복구한 스크립트와 직전 정상 배치의 스크립트는 바이트 및 SHA-256이 동일합니다.
별도 수정이나 추가 이동, 배경 재제작을 하지 않았습니다.

| 대상 | 복구된 u/v | 표시 폭 | 비고 |
|---|---|---|---|
| 칠판 | 500 / 14 | 300 | 깊이 정렬값에 -10 보정 |
| 교탁 | 500 / 165 | 210 | 이전 배치 유지 |
| 뒤쪽 큰 책장 | 80 / 125 | 113 | 충돌 중심 80 / 145로 함께 복구 |
| 케이네 | 690 / 110 | 기존 높이 126 | 이미지/위치 유지 |

학생 4명과 책상 배치, 케이네 이미지/초상화/대화창, 수업 메뉴는 그대로입니다.
정식 GitHub Pages 및 Firebase 설정/클라우드 저장에 접근하거나 변경하지 않았습니다.
과거 LAYOUT_V2 문서와 결과는 취소된 배치의 이력이며 현재 상태 설명이 아닙니다.

## 1. 가구가 배경에 포함되는지
room-shell.png는 벽·바닥·창문·기둥·햇빛 등이 있는 가구 없는 교실 이미지입니다.
칠판·교탁·책장은 classroom-atlas.png의 각 영역을 잘라 읽는 독립 오브젝트입니다.
배경 이미지에 칠판/교탁/책장이 중복으로 그려져 있지는 않습니다.

원본 아틀라스 영역(x,y,w,h):
- 교탁: 420,118,444,361
- 책장: 928,2,291,479
- 칠판: 1280,30,479,469
실제 표시 전 alphaBounds()가 알파 32 초과 영역을 찾아 투명 여백을 줄여 읽습니다.
이미지 파일을 변경하는 처리는 아닙니다.

## 2. 위치·깊이·가림 처리
### 위치
서당의 xy(u,v)는 다음 2D 아핀 변환입니다.
x = 705 + 0.697u - 0.56v
y = 335 + 0.268u + 0.283v
이는 그림 배경 위에 정한 배치 좌표이며, 벽과 가구가 서로 붙는 3D 물리 구조가 아닙니다.

addProp()이 변환 좌표, 이미지 영역 번호, 표시 폭을 등록합니다.
sprite()는 알파 영역의 하단 중앙을 이 좌표에 맞춰 세워 그립니다.
높이는 지정 폭과 이미지의 가로세로 비율로 계산합니다.
벽 접착점, 가구 뒷면 접점, 벽걸이 높이 같은 별도 기준은 정의되어 있지 않습니다.

### 깊이
gensokyo_rpg.html의 그리기 단계에서 플레이어/NPC/가구/지형을 하나의 큐에 넣고
각 y 값의 오름차순으로 그립니다. 가구는 기본적으로 등록 위치 y+depthOffset을 사용합니다.
칠판의 depthOffset은 -10이고, 교탁과 책장은 0입니다.
가구는 한 장의 스프라이트 전체가 하나의 깊이 값을 사용합니다.
개별 모서리/책장 뒷면/칠판 판면에 별도 깊이가 있는 구조는 아닙니다.

### 가림
스프라이트끼리는 위의 그리기 순서와 PNG 알파로 앞뒤를 표현합니다.
서당 지형의 별도 가림 폴리곤은 앞쪽 좌우 난간 2개입니다.
정해진 frontY에서 해당 폴리곤으로 화면을 잘라 캐시한 배경을 다시 그립니다.
뒤쪽 벽/창문이 가구를 부분적으로 가리는 별도 마스크나 벽면 장착 처리는 없습니다.

### 충돌과 그림자
책상/교탁/책장의 이동 차단은 footprint()로 만든 별도 바닥 폴리곤입니다.
이 충돌 폴리곤은 화면에 가구를 그리거나 벽에 밀착시키는 역할을 하지 않습니다.
가구용 sprite()는 PNG만 그리며 별도의 접촉 그림자를 만들지 않습니다.
PNG 안의 명암은 그대로 표시되지만 배경의 빛/벽면에 맞춰 자동 조정하지 않습니다.

## 3. 떠 보이는 원인
코드와 원본 그림을 확인한 사실을 바탕으로 다음 시각적 원인이 있다고 판단합니다.

칠판 원본에는 양쪽 아래에 두꺼운 받침이 있습니다. 즉, 벽걸이형보다 스탠드형에 가까운
디자인인데 현재는 이미지 하단 중앙 한 점만 기준으로 배치하고 있습니다.
받침의 실제 바닥 접점/벽과의 관계가 명시되어 있지 않고 별도 접촉 그림자도 없어,
판면과 교탁의 간격만으로 보면 공중에 떠 있는 것처럼 읽힐 수 있습니다.
단순히 그림 전체를 아래로 내리면 판면뿐 아니라 받침 전체와 깊이 기준까지 함께 변해
원래의 벽·교탁 관계가 더 어색해질 수 있습니다.

책장 또한 두께와 측면이 그려진 원본 이미지입니다. 이미지 하단 중앙은 책장 뒷면이
벽에 닿는 지점과 다릅니다. 현재는 뒷면의 벽 접점이 없고 배경의 벽 하단선과 자동으로
맞추지 않으므로, 이미지 좌표를 위로 밀기만 하면 창문이나 벽 프레임에 걸쳐 보일 수 있습니다.
깊이 정렬만으로 이 접촉 문제를 해결할 수는 없습니다.

지난 수정은 이 차이를 확인하지 않고 표시 좌표와 충돌 위치를 이동한 것이 문제였습니다.
이미지가 배경에 중복으로 들어 있거나 저장 데이터가 잘못 복구되어 생긴 문제는 아닙니다.

## 가장 안전한 다음 수정 방법 — 현재는 미적용
1. 현재 복구 상태를 기준본으로 고정합니다.
2. 가구 그림을 움직이기 전에 바닥 접점/책장 뒷면/벽 하단선을 검토용 표식으로 대조합니다.
3. 서당 가구에 한해 '그림 표시 기준', '바닥 접점', '깊이 기준'을 구분하는 최소 보정을 검토합니다.
4. 원본 칠판을 유지한다면 스탠드형으로 보고 받침이 바닥에 놓이는 기준으로 맞추는 것이 안전합니다.
   벽걸이형이 목표라면 기존 받침을 가진 그림을 좌표만 옮겨 해결하려 하지 말고,
   원본 변경 허용 여부와 사용할 디자인을 먼저 정해야 합니다.
5. 책장은 뒷면의 바닥 접점을 벽 하단에 맞춘 한 가지 후보를 먼저 화면으로 비교하고,
   그 후보가 자연스러운 경우에만 충돌과 깊이를 같은 기준으로 맞춥니다.

현재는 위 보정, 새 그림자, 새 고정 구조, 가구 이동, 배경 수정 중 어느 것도 하지 않았습니다.
새 일본어 학습 기능도 추가하지 않았습니다.

## 실행
전체 ZIP을 새 폴더에 압축 해제하고 START_SCHOOL_DEV.bat를 실행합니다.
이전 개발 서버 창이 열려 있으면 닫습니다. 개발 주소 localhost:8896은 동일합니다.
직전 layout_v2 개발본을 이미 가지고 있다면 복구 패치를 그 루트에 덮어써도 됩니다.
캐시가 남으면 Ctrl+F5로 새로고침합니다. 저장 데이터를 삭제하지 마세요.

## 검증 범위
복구 스크립트의 원본 일치 및 다른 기존 파일 동일성을 비교합니다.
F키 입장 → 케이네까지 경로 이동 → 대화/표정/수업 메뉴 → 인벤토리 →
출구까지 경로 이동 → F키 퇴장 및 테스트 로컬 저장의 새로고침 복원을 확인합니다.
실제 Google 로그인/Firestore 동기화와 전 스테이지 완주는 다시 시험하지 않습니다.
최신 실제 결과는 school/RESTORE_TEST_RESULTS.json에 기록합니다.
